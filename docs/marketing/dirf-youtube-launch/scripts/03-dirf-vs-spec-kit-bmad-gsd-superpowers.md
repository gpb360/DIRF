### 00:00 — Stop searching for one winner

**VOICEOVER**

Spec Kit, BMAD, GSD, Superpowers, and DIRF can all improve agent work. They do

### 00:45 — Compare by job

**VOICEOVER**

Feature-count comparisons get silly fast. One project has more agents. Another
has more integrations. A third has a stricter lifecycle. More is useful only
when it matches the job you need done.

I use five questions.

How much method do you want? How fixed should the lifecycle be? Does the tool
start from its own catalog or from your installed capabilities? How does state
survive sessions and worktrees? What evidence or authority does “done” require?

Keep those questions in view as we walk through the options.

**VISUAL**

- Five-question comparison spine.
- Each project will light up the questions it emphasizes.

### 01:35 — GitHub Spec Kit

**VOICEOVER**

GitHub describes Spec Kit as a specification-driven development toolkit and an
intent-driven harness. Its default path is easy to understand: specification,
plan, tasks, implementation. Each phase creates a Markdown artifact that feeds
the next.

Use Spec Kit when you want structured intent to lead implementation and your
team benefits from a recognizable spec-driven path. It also supports many
coding-agent integrations, so portability is part of its public design.

Where can DIRF fit? Before the Spec Kit workflow, DIRF can inspect the task and
host, choose specification work when it fits, save the attempt, and preserve
the canonical handoff around that work. DIRF should not recreate Spec Kit's
templates badly. It should route into the installed capability and keep the
continuity contract.

**VISUAL**

- Spec Kit lane: Spec → Plan → Tasks → Implement.
- DIRF preflight appears before the lane; canonical handoff runs beneath it.
- Source callout: official Spec Kit documentation.

### 03:00 — BMAD Method

**VOICEOVER**

BMAD presents a broader agile method. Its current documentation emphasizes
scale-adaptive planning, specialized roles, structured workflows, and a full
delivery lifecycle. It is the strongest fit here for someone who wants a guided
method with analyst, product, architecture, development, and quality roles.

That depth is an advantage when the work needs it. It can also be more method
than a small, narrow task requires.

DIRF's useful relationship is selective. A playbook can request a capability.
If the best installed capability comes from BMAD, DIRF can select it for that
stage. The viewer keeps the expert workflow without making every task enter the
entire lifecycle.

Use BMAD when you want the method. Add DIRF when you also want live capability
routing and canonical attempt continuity around a mixed toolset.

**VISUAL**

- BMAD lane expands into specialist roles.
- Small task bypasses the full fan-out; large task uses it.
- Source callout: official BMAD repository and workflow map.

### 04:20 — GSD

**VOICEOVER**

GSD is an opinionated system for planning and executing substantial work. Its
architecture supports multiple AI coding runtimes through a command and
workflow structure, and its ecosystem covers project creation, milestones,
phase planning, execution, review, verification, and more.

Use GSD when you want a deep project and milestone operating method. It is a
good answer for builders who prefer a strong lane and are willing to learn its
commands.

DIRF can treat installed GSD skills as capabilities when their descriptions
match the task. It can also preserve a project handoff and portfolio state
outside an individual GSD run.

The recording-day demo must prove the exact routed capability. If DIRF chooses
something else, show that honestly and explain the metadata decision.

**VISUAL**

- GSD lane: Project → Phase → Plan → Execute → Verify.
- A DIRF capability selector points to one installed GSD stage only after a
  match.
- Source callout: GSD architecture documentation.

### 05:35 — Superpowers

**VOICEOVER**

Superpowers describes itself as a software-development methodology built from
composable skills and initial instructions. Its behavior begins early: clarify
the idea, form a spec, plan the work, implement in bounded steps, and verify.

Use Superpowers when you want the agent to follow a disciplined development
method inside one of its supported hosts. Its skills are the product's center
of gravity.

DIRF's center of gravity is routing and state. It can discover installed
Superpowers skills, choose a relevant one, and place it inside a larger task
route. Progressive disclosure remains valuable in both systems.

That combination is practical: Superpowers can teach a stage how to behave;
DIRF can decide when that stage belongs in this task and preserve what happened
after the session changes.

**VISUAL**

- Skill tiles remain collapsed until selected.
- One Superpowers skill joins a DIRF route.
- Source callout: official Superpowers repository.

### 06:50 — DIRF's layer

**VOICEOVER**

DIRF is the thinnest method in this comparison on purpose.

It reads the task and repository. It scans installed skills and agents across
supported host and project locations. It routes capabilities into a lean
workflow. It renders Markdown for the agent and HTML for the person. It saves
the attempt and one canonical project handoff. It can attach completion,
decision, and evidence gates. Current main also includes a vendor-neutral
governed-execution layer for evaluating higher-risk action segments.

That makes DIRF strongest for a mixed environment. You already have useful
methods, agent hosts, and custom skills. You need a small layer that selects,
bounds, records, and hands off the work without demanding a reset.

The cost of that flexibility is that DIRF does not give every task one famous,
opinionated lifecycle. Routing quality depends on good playbooks, accurate skill
metadata, and an honest task description.

**VISUAL**

- Full DIRF map: live stack → route → attempt → evidence → handoff.
- Show a capability gap as a real amber gap, not a silently substituted tool.

### 08:20 — Four practical stack choices

**VOICEOVER**

Here are four sensible choices.

Choice one: Spec Kit alone. Pick this when the spec-driven path is the workflow
you want and its integrations cover your environment.

Choice two: BMAD or GSD alone. Pick one when you want a broad, opinionated
delivery method and prefer consistency over mixing several approaches.

Choice three: Superpowers alone. Pick it when behavior inside the coding agent
is the main gap and the supported host setup fits.

Choice four: DIRF around one or more of them. Pick this when you already have a
mixed stack, need task-specific routing, and care about canonical continuity
across sessions, projects, or worktrees.

You can also use DIRF alone with its bundled fallback agents and native
playbooks, but the agnostic value becomes clearer when it has real installed
capabilities to choose from.

### 10:15 — Close

**VOICEOVER**

The honest decision is based on the layer you need.

Choose the method when you want the method. Choose the skill system when you
want reusable behavior. Choose the connection standard when you need tools and
data. Add DIRF when you need the task routed through your live stack and the
state preserved after the current session disappears.

If you already use one of these projects, keep it installed. Run a DIRF skill
scan, preview a real task, and see whether the route selects the capability you
expected.
