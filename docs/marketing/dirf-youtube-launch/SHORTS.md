# DIRF Shorts system

## Purpose

Use Shorts to introduce one sharp problem or mechanism, then send interested
viewers to the matching full episode. A Short must stand alone. It should not
feel like an arbitrary sentence cut from a longer video.

## Format

- 20–55 seconds for the first testing batch
- 9:16, 1080 × 1920
- one claim, one proof, one next step
- visible change or proof in the first second
- burned-in captions with corrected technical names
- related-video link to the source episode when available

## Framework

Primary: G.R.A.B. for a fast problem, relatable moment, action, and benefit.

Alternative: PAS when the failure mode is more compelling than the product
mechanism. Test the two openings on similar concepts rather than rewriting the
same Short with cosmetic differences.

## Recording pattern

Write each Short as four beats:

1. **Get attention:** state the failure or surprising distinction.
2. **Relate:** name the operator moment in one sentence.
3. **Action:** show the command, artifact, or decision.
4. **Benefit:** tell the viewer what becomes easier and point to the full video.

## Test plan

Publish in matched pairs only after the long-form source is live. Change one
major variable per pair: problem-led versus mechanism-led hook, terminal-first
versus face-first visual, or 25 seconds versus 45 seconds. Do not change the
hook, duration, visual, and CTA at once.

Evaluate within each format. For Shorts, prioritize engaged views,
chose-to-view rate, average percentage viewed, rewatches, subscribers, and
related-video traffic. Raw starts alone are not the comparison metric.
